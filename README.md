# IO — your shield against the ban

AI-запросы уходят в интернет с IP **сервера**; исполнение агента остаётся на
твоей машине. Наружу торчит только SSH. Настоящие ключи провайдеров живут
только на сервере — клиент держит заглушку.

## Из чего состоит

Один репозиторий, две стороны:

| Папка | Где крутится | Что это |
|---|---|---|
| [`ai-bridge/`](ai-bridge/) | сервер (Ubuntu/Debian) | Caddy на `:8801`, loopback-only, подставляет реальный ключ |
| [`client/`](client/) | твой ПК | SSH-туннель + конфиг Hermes + плагин квот |

```
локальный клиент (Hermes / claude CLI)
  → http://127.0.0.1:8801/...          (локальный порт)
  → SSH-туннель (ключ, автоперезапуск) (единственное шифрованное звено)
  → Caddy на сервере, 127.0.0.1:8801   (loopback only, ключи живут тут)
  → api.z.ai / api.anthropic.com       (провайдер видит только сервер)
```

## Почему это «щит»

- **Ключ не выходит из дома.** Реальный `ZAI_KEY`/`OPENAI_TOKEN` лежит только в
  `/opt/ai-bridge/env` на сервере. Клиент шлёт заглушку; сервер перезаписывает
  заголовок `Authorization` на каждый запрос.
- **Нет фолбэка на прямое подключение.** Туннель упал — чаты встали, утечек нет.
- **Провайдер видит Linux-клиента с IP сервера** (`x-stainless-*` и
  `user-agent` перезаписываются на сервере).
- **Опциональный kill-switch** (`client/tunnel/`): если туннель лежит, Windows
  firewall блокирует прямой outbound-443 к провайдерам, чтобы ничего не утекло
  мимо туннеля.

## Безопасность

Смотри [`.gitignore`](.gitignore) — полный список того, что не должно попадать
в git. Коротко: приватные SSH-ключи, `env`/`.env`/`zai-key`/`openai-token`,
базы Hermes (`*.db`), сессии, кеши, логи, MCP-токены.
